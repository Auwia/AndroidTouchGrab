# AndroidTouchGrab

A lightweight Android utility that temporarily disables physical touchscreen input while keeping ADB input control available.

AndroidTouchGrab uses the Linux `EVIOCGRAB` ioctl to exclusively grab an Android/Linux input device. This prevents physical events from that device from reaching Android while allowing the device to remain controllable through ADB.

## Why AndroidTouchGrab?

AndroidTouchGrab is useful when an Android device has a damaged or malfunctioning touchscreen that generates unwanted or ghost touch events.

It is particularly useful for devices controlled remotely or through automation, where physical touchscreen events can interfere with ADB-generated input.

Typical use cases include:

- Devices affected by ghost touches
- Broken or partially damaged touchscreens
- Android automation through ADB
- Remote device control
- Dedicated Android automation devices
- Test devices where physical touch input should be temporarily disabled

## How It Works

Android exposes hardware input devices through Linux event interfaces such as:

    /dev/input/event2

AndroidTouchGrab opens the selected input device and requests exclusive access using:

    ioctl(fd, EVIOCGRAB, 1);

While the grab is active, physical events generated by that input device are prevented from being delivered normally to Android.

ADB-generated input remains available, so commands such as:

    adb shell input tap 500 1000

and:

    adb shell input swipe 500 1500 500 500 300

can still be used.

When AndroidTouchGrab exits, the `EVIOCGRAB` lock is released and normal input resumes.

## Requirements

- Android device
- ADB access
- Permission to open the target `/dev/input/event*` device
- ARM64/AArch64 device when using the provided build configuration
- ARM64 cross-compiler when building on a Debian/Ubuntu host

Access to `/dev/input/event*` depends on the permissions and security configuration of the Android device.

## Finding the Touchscreen Input Device

Connect the Android device and inspect its input devices:

    adb shell getevent -lp

Look for the entry corresponding to the touchscreen.

For example:

    add device 2: /dev/input/event2
      name: "touchscreen"

The exact event number varies between devices.

Do not assume that the touchscreen is always `/dev/input/event2`.

Selecting the wrong event device may temporarily block another input device instead.

## Building

The included `build.sh` script cross-compiles AndroidTouchGrab as a statically linked ARM64/AArch64 binary.

On Debian or Ubuntu, install the cross-compiler if necessary:

    sudo apt install gcc-aarch64-linux-gnu

Make the build script executable:

    chmod +x build.sh

Build AndroidTouchGrab:

    ./build.sh

A successful build produces:

    ./touch_grab

The generated binary can be inspected with:

    file touch_grab

Example output:

    touch_grab: ELF 64-bit LSB executable, ARM aarch64, statically linked

The build enables the following compiler warnings:

    -Wall -Wextra -Wpedantic

and uses:

    -O2 -static

## Installing on Android

Copy the binary to the Android device:

    adb push touch_grab /data/local/tmp/touch_grab

Make it executable:

    adb shell chmod +x /data/local/tmp/touch_grab

## Command-Line Usage

Display the program version:

    adb shell /data/local/tmp/touch_grab --version

Example:

    AndroidTouchGrab 1.0.0

Display help:

    adb shell /data/local/tmp/touch_grab --help

AndroidTouchGrab also supports the short options:

    -h
    -v

## Running

Specify the touchscreen input device explicitly:

    adb shell /data/local/tmp/touch_grab /dev/input/event2

Replace `/dev/input/event2` with the correct event device for your hardware.

When the grab succeeds, AndroidTouchGrab reports:

    AndroidTouchGrab 1.0.0
    Input device grabbed: /dev/input/event2
    Physical input events from this device are now blocked.
    ADB input control remains available.
    Press Ctrl+C to release the device.

AndroidTouchGrab also has a default input device:

    /dev/input/event2

Therefore this is also valid:

    adb shell /data/local/tmp/touch_grab

However, explicitly specifying the input device is recommended because event numbers vary between Android devices.

## Testing ADB Control

While AndroidTouchGrab is running, physical input from the grabbed touchscreen should no longer affect Android.

Open a second terminal and test ADB-generated input:

    adb shell input tap 500 1000

or:

    adb shell input swipe 500 1500 500 500 300

ADB-generated input should continue to work while the physical touchscreen remains blocked.

## Stopping AndroidTouchGrab

Press:

    Ctrl+C

AndroidTouchGrab handles `SIGINT` and `SIGTERM`, releases the `EVIOCGRAB` lock, closes the input device, and exits.

Expected output:

    Releasing input device...
    Input device released.

Normal physical touchscreen input should then resume.

## Troubleshooting

### Permission denied

If AndroidTouchGrab reports an error similar to:

    Error: cannot open input device '/dev/input/event2': Permission denied

the current shell does not have permission to open that input device.

Input-device permissions depend on the Android version, manufacturer, kernel configuration, SELinux policy, and device configuration.

### No such file or directory

If you see:

    Error: cannot open input device '/dev/input/event2': No such file or directory

verify the available input devices:

    adb shell getevent -lp

Then run AndroidTouchGrab with the correct `/dev/input/eventX` path.

### Physical touch still works

Verify that the selected event device actually corresponds to the touchscreen.

Some Android devices may expose multiple touch-related input devices.

Use:

    adb shell getevent -lp

to inspect the available devices.

### Wrong input device was grabbed

Stop AndroidTouchGrab with:

    Ctrl+C

The input device will be released.

Then identify the correct event device before restarting the program.

## Safety Notes

AndroidTouchGrab does not permanently disable the touchscreen.

The input device remains grabbed only while the AndroidTouchGrab process is running and keeps the device open.

When the program terminates normally through `SIGINT` or `SIGTERM`, it explicitly releases the `EVIOCGRAB` lock.

If the process terminates unexpectedly, the operating system closes the file descriptor and the exclusive grab is released.

Be careful when selecting the input device. Grabbing the wrong `/dev/input/event*` device can temporarily disable another hardware input source, such as buttons, keyboards, controllers, or other connected input devices.
